# Aplicaciones gráficas por SSH — MobHector 1.5.1

## Windows: sin depender de MobaXterm

1. Instala o actualiza MobHector con `instalar_o_actualizar.bat` desde el ZIP completo.
2. El paquete ya incluye VcXsrv y sus bibliotecas: no necesitas instalarlo aparte.
3. Edita la sesión SSH. En **Aplicaciones gráficas → X11**, marca **Permitir aplicaciones X11 de este servidor de confianza**.
4. Selecciona **Usar servidor X11 integrado (Windows)** y deja vacía la ruta del ejecutable.
5. Guarda y reconecta. En la terminal remota ejecuta `echo "$DISPLAY"`. El servidor SSH debe asignar el display; no lo establezcas manualmente.
6. Ejecuta la aplicación gráfica remota. Si hay un segundo salto, usa `ssh -X usuario@destino` desde la primera sesión que ya tiene DISPLAY.

El modo automático inicia una instancia de VcXsrv por conexión SSH, con display disponible entre 60 y 99, autenticación MIT-MAGIC-COOKIE-1 y renderizado sin WGL. La cierra al desconectar. No requiere iniciar MobaXterm. El ZIP incluye el servidor en `vendor/vcxsrv`, con sus bibliotecas, fuentes y datos de teclado. Consulta THIRD_PARTY_X11.md para las licencias y el código fuente original.

## Linux o servidor X existente

Selecciona **Usar servidor X11 existente**. En Linux deja los campos vacíos para usar `DISPLAY` y `XAUTHORITY` del proceso; en ausencia de XAUTHORITY se consulta `~/.Xauthority`. También puedes elegir el archivo y display explícitamente. Sólo se aceptan displays locales (`:0`, `unix:0`, `localhost:10.0` o `127.0.0.1:0.0`). No se acepta una IP de red como destino del servidor X.

En Windows, el modo existente requiere un display TCP local y el archivo Xauthority con el que se inició ese servidor X. No se admite un servidor sin autenticación.

## Requisitos del servidor SSH

El administrador debe permitir `X11Forwarding` y disponer de `xauth`. En CentOS Stream 9 el paquete es `xorg-x11-xauth`. Si el servidor rechaza X11 o el servidor X local no está disponible, se muestra un error; puedes desactivar X11 en la sesión y reconectar para seguir usando la terminal normal.

Para el caso de dos saltos: primero confirma DISPLAY en el servidor inicial; después entra con `ssh -X` al destino y vuelve a confirmarlo. Cambios de usuario con `su`, políticas de SSH y `tmux` pueden requerir configuración adicional administrada por el usuario.

## Alcance y autenticación

- Implementado en sesiones SSH estándar guardadas. Quick Connect debe guardarse/editarse para habilitar X11. El flujo especial Platón/su no añade ni transfiere cookies automáticamente.
- La cookie local no se envía al servidor SSH. Se genera una cookie distinta por terminal, se verifica al recibir cada conexión y sólo entonces se conecta al servidor X local y se sustituye la cookie.
- No se escriben cookies en config.json, exportaciones ni logs. El modo VcXsrv utiliza un archivo temporal de autorización dentro del directorio temporal del usuario, eliminado al cerrar normalmente.
- X11 está desactivado por defecto y también tras importar sesiones. Activarlo concede acceso a la pantalla X a aplicaciones del servidor remoto: es un modo para servidores de confianza, sin aislamiento SECURITY equivalente al modo no confiable de OpenSSH.
- MobHector no abre un listener X11 propio. VcXsrv sí escucha por TCP con autenticación; el alcance del listener depende de VcXsrv. No se abre el firewall, no se ejecuta `xhost +` y no se utiliza `-ac`. No autorices acceso desde redes externas para este uso local.
- Máximo 16 conexiones gráficas simultáneas por conexión SSH; handshake limitado y con timeout. Al desconectar se cierran canales y conexiones locales.
- Validación: protocolo SSH/X11 real con Paramiko y extremo X simulado; cookies, intercambio bidireccional y cierre. No se afirma prueba completa de VcXsrv en Windows ni de tu cadena real de servidores.

Fuentes: https://docs.paramiko.org/en/stable/api/channel.html#paramiko.channel.Channel.request_x11 y https://www.x.org/guide/communication/ .
